# Реестр учёта первичных документов

Локальное приложение без сервера и установки — набор статических файлов,
работает через File System Access API прямо в браузере (Chrome / Edge / Opera).

## Структура проекта

```
index.html          — голая разметка (структура страницы, без стилей и логики)
css/style.css        — все стили
js/version.js          — версия приложения и история изменений (патч-ноуты)
js/config.js             — конфигурация по умолчанию (виды документов, контрагенты)
js/storage.js              — доступ к папке на диске, чтение/запись registry.json и config.json
js/app.js                    — реестр: таблица, фильтры, справочники, карточка документа
js/single.js                    — одиночный режим: пакетная загрузка нескольких файлов
js/group.js                       — групповой режим: карточки групп, PDF-превью, нарезка PDF
js/vendor/                          — библиотеки pdf.js и pdf-lib (подгружаются только при первом обращении к превью/нарезке PDF)
CHANGELOG.md                          — история версий (то же самое, что и кнопка версии в приложении)
```

Текущая версия и список изменений видны прямо в приложении — кнопка
справа внизу («v4.2.0» и т.п.), а также в файле `CHANGELOG.md`.

## Добавление документов

В окне «Новый документ» есть переключатель **Отдельные файлы / Разбить
PDF на документы** — оба режима теперь работают в одном полноэкранном окне с
одинаковой раскладкой: список карточек слева, превью справа.

### Отдельные файлы (пакетная загрузка)

1. Нажмите «Выбрать файлы» — можно выбрать сразу несколько (каждый файл
   станет отдельным документом). «Кол-во документов» считается
   автоматически.
2. Слева появится карточка на каждый файл. Из имени файла приложение
   пробует угадать дату, номер и вид документа — если не угадало,
   заполните вручную.
3. Клик по карточке показывает превью её файла справа; пока карточка не
   выбрана, справа — миниатюры всех загруженных файлов.
4. Подтвердите карточку галочкой (✓) — в реестр попадут только
   подтверждённые и полностью заполненные (вид + номер) карточки.
5. **«Добавить документы»** — создаёт документ на каждую подтверждённую
   карточку, прикрепляя соответствующий файл.

### Разбить PDF на документы

1. Укажите **кол-во групп** (по одной на каждый документ внутри общего
   PDF) — стрелочками или вручную. При изменении количества данные уже
   заполненных групп не теряются (обрезаются только лишние в конце).
2. Прикрепите **общий PDF** (кнопка справа сверху) — справа появится
   постраничная раскладка.
3. Для каждой группы слева заполните вид документа, номер, дату,
   контрагента и т.д. — бейдж группы наверху карточки подсвечивается,
   когда обязательные поля (вид + номер) заполнены.
4. Укажите **кол-во страниц** для группы (если документ на несколько
   листов) и перетащите бейдж группы на нужную страницу справа — с неё
   будет захвачено столько ВИДИМЫХ страниц подряд (удалённые
   пропускаются), сколько указано.
5. Подтвердите галочкой (✓) — рядом с бейджем в карточке или прямо на
   странице. Занятые страницы пропадают из общего пула. Кнопка сброса
   (↺) освобождает их обратно.
6. У каждой страницы есть кнопки поворота (⟳) и удаления (✕) — удалённые
   страницы можно вернуть кнопкой «Показать скрытые страницы».
7. **«Добавить документы»** — исходный PDF нарежется на отдельные файлы
   (по тем же правилам именования, что и в одиночном режиме, с учётом
   поворота) и создаст документ на каждую подтверждённую группу.

Групповой режим требует Chrome/Edge (как и весь остальной функционал) и
при первом включении подгружает `pdf.js`/`pdf-lib` из папки `js/vendor/`
— это локальные файлы, интернет не требуется.

## Как запустить

1. Откройте `index.html` в Chrome или Edge (двойным кликом, либо через
   «Открыть с помощью»).
2. Нажмите **«Выбрать папку»** и укажите папку для хранения данных —
   например, ту же, где лежат файлы приложения, или отдельную.
3. Готово. Всё сохраняется прямо в эту папку:
   - `registry.json` — документы, стадии, история переходов;
   - `config.json` — справочники: виды документов (с префиксами) и контрагенты;
   - сами вложения — плоско, рядом, без подпапок.

При повторном открытии браузер может попросить заново подтвердить доступ к
папке — нажмите «Подтвердить доступ к папке».

Если открытие напрямую (`file://`) не срабатывает — поднимите простейший
локальный сервер без установки (модуль есть в Python из коробки):

```bash
cd путь/к/папке/с/index.html
python -m http.server
```

и откройте `http://localhost:8000`.

## Виды документов, префиксы и контрагенты

Кнопка **«Справочники»** в шапке открывает управление двумя списками:

- **Виды документов** — у каждого вида есть короткий **префикс**, который
  используется при сборке имени документа и имени файла вложения. Например,
  вид «УПД» с префиксом «УПД» + номер «2594» + дата «31.07.26» дают:

  ```
  УПД №2594 от 31.07.26
  ```

- **Контрагенты** — простой список названий.

Оба списка также можно пополнять «на лету»: в форме добавления документа при
выборе вида или контрагента внизу списка есть пункт «+ Новый...» — выбрав
его, можно тут же вписать новое значение, и оно попадёт в общий справочник
для всех следующих документов.

## Имя документа и имя файла — без ручного ввода

Раньше при добавлении файла нужно было вручную придумывать ему имя. Теперь
это не требуется: поле «Имя документа» — это просто номер, а полное
отображаемое имя (и, соответственно, имя файла на диске) собирается
автоматически по формуле:

```
{Префикс вида} №{номер} от {дата}
```

Если к документу прикрепляется несколько версий файла, к имени добавляется
номер версии: «УПД №2594 от 31.07.26 v2.pdf». Старые версии не
перезаписываются и остаются на диске, пока их не удалить вручную кнопкой в
карточке документа.

## Ограничения

- Работает только в Chrome / Edge / Opera (десктоп) — File System Access API
  не поддерживается Firefox и Safari.
- Разрешение на папку иногда приходится подтверждать заново при перезапуске
  браузера — это политика безопасности самого браузера, не приложения.
- Рассчитано на одного пользователя (без сети, без многопользовательского
  доступа).
